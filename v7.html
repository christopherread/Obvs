Obvs

A .NET library for messaging between services: commands, events, requests and responses over RabbitMQ, Kafka, NATS, ActiveMQ, Azure Service Bus or Amazon SQS, with handlers, awaitable requests and Reactive Extensions streams.

What's new in v7

v7 makes Obvs a library you host, test and observe the way you do the rest of a modern .NET app. The Rx streams that were v6's whole API are still there; most of what's new is additive, and v6 and v7 apps work together on the same broker, so you can move one app at a time.

  • Hosting through dependency injection. services.AddObvs(...) configures the bus, and IServiceBus and IServiceBusClient come from the container. The bus starts and stops with the host. Its configuration is checked at startup, and every problem is reported in one ObvsConfigurationException, each saying how to fix it. Without a host, ObvsBus.StartAsync(...) does the same.
  • Every transport configured the same way: UseRabbitMq, UseKafka, UseNats, UseNatsJetStream, UseActiveMq, UseAzureServiceBus and UseAmazonSqs, each with an options class, from configuration or code.
  • New transports. Azure Service Bus and Amazon SQS and SNS, where a service's instances share its command and request queues, each bus has its own subscription to events, and messages are settled after their handler: completed, delivered again on failure, and dead-lettered after MaxDeliveryAttempts. NATS JetStream works the same way. Kafka supports Confluent Cloud, Amazon MSK and Azure Event Hubs.
  • Handlers and awaitable requests: HandleCommand, HandleEvent and HandleRequest, as lambdas or classes from the container, with MaxConcurrency; RequestAsync; and the streams as IAsyncEnumerable with ReadEventsAsync. Every send takes a CancellationToken, which reaches the broker.
  • System.Text.Json by default, reading and writing the same JSON as v6's Newtonsoft serializer. Any serializer can be gzipped with Compressed().
  • Observability: OpenTelemetry traces and metrics, with trace context carried in each message's headers on every transport, and logging through Microsoft.Extensions.Logging.
  • Testing: Obvs.Testing's in-memory transport and ObvsTestHarness, which waits for a message as soon as it's sent, with virtual time.
  • Analyzers, built into the Obvs package, report common mistakes as you type, with code fixes.
  • For agents: each service's contract as an AsyncAPI document, a test that catches breaking contract changes, an MCP server for development buses, llms.txt, and documentation whose every snippet is compiled and tested.

Before and after

v6:

IServiceBus bus = ServiceBus.Configure()
    .WithRabbitMQEndpoints<IOrderMessage>()
        .Named("orders")
        .ConnectToBroker("amqp://localhost:5672")
        .SerializedAsJson()
        .AsClientAndServer()
    .UsingConsoleLogging()
    .Create();
bus.Commands.OfType<PlaceOrder>().Subscribe(async command =>
{
    await bus.PublishAsync(new OrderPlaced(command.OrderId));
});

v7:

builder.Services.AddObvs(obvs => obvs
    .AddService<IOrderMessage>("orders", service => service
        .UseRabbitMq(options => options.Uri = new Uri("amqp://localhost:5672"))));

// IServiceBus and IServiceBusClient are in the container. The bus starts with the host.
service.HandleCommand<PlaceOrder>(async (command, context, ct) =>
{
    await context.PublishAsync(new OrderPlaced(command.OrderId), ct);
});

// Or a class from the container
service.HandleCommand<PlaceOrder, PlaceOrderHandler>();

Requests, in v6 and v7:

var quote = await bus.GetResponses(new GetQuote("sku-1"))
    .OfType<Quote>().Take(1).Timeout(TimeSpan.FromSeconds(5)).ToTask();
var quote = await client.RequestAsync<GetQuote, Quote>(new GetQuote("sku-1"), TimeSpan.FromSeconds(5), ct);

What changed since v6

  • Configuration. ServiceBus.Configure() still works for v6 apps, and is marked obsolete in favour of AddObvs.
  • Packages. The MsgPack.Cli, NetJSON, XML and YAML serializers, Obvs.Monitoring.* and Obvs.Logging.NLog stay on v6: use System.Text.Json, OpenTelemetry and Microsoft.Extensions.Logging. Obvs.Serialization.MessagePack is now MessagePack-CSharp.
  • Target frameworks: net472, netstandard2.0 and net10.0.

The migration guide has the details: before and after for each change, and what v6 and v7 apps on one broker share.
